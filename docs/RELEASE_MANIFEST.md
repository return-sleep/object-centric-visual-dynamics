# Release manifest

This document freezes the scope and provenance of the first public release.
It is intentionally narrower than the authors' internal experiment workspace.

## Included experiments

| Dataset | Task | Public protocol | Main entry point |
|---|---|---|---|
| BallsCF | video prediction | 3 conditioning frames, 25 predictions, 112x112 | `main.py` |
| BlocktowerCF | video prediction | 1 conditioning frame, 25 predictions, 112x112 | `main.py` |
| Simb | trajectory prediction | 4 conditioning frames, 20 predictions, 64x64 | `train_simb_dynamics.py` |
| OBJ3D | video prediction | train on 6+14 random windows, evaluate 6+44 at 128x128 | `main.py` |

The exact public commands are stored in `configs/*.json` and generated by
`tools/run.py`. Traffic-specific code, data, checkpoints, and results are not
part of this release.

## Source provenance

The model implementation was curated from the internal `portable_core`
snapshot. Only the following families were migrated:

- `src/KeypointNet/Derendering*.py`
- `src/baseline_model/GN_modules.py`
- the inference helpers imported by the main training code
- CoPhy, Simb, and OBJ3D loaders
- `main.py`, `train_derendering.py`, `train_simb_dynamics.py`, and
  `utils.py`

No submission correspondence, reviewer material, internal scheduler rules,
training logs, predictions, raw datasets, or model weights were migrated.

## Frozen reference configurations

- BallsCF and BlocktowerCF use the submitted two-stage recipes.
- Simb uses the paper's 4-to-20 trajectory protocol. The perception trainer
  may load a longer clip internally, but the public dynamics evaluation is
  fixed to 20 predicted steps.
- OBJ3D uses the six-keypoint, eight-coefficient, 128x128 perception model
  (`num_filter=64`) and a relational dynamics model trained on random
  6+14-frame windows. Public evaluation is a 44-step free-running rollout.

OBJ3D had multiple internal refinement runs. The first public release exposes
one deterministic recipe and one checkpoint slot rather than the full sweep.
The published checkpoint must be paired with `configs/obj3d.json`.

## Checkpoint-to-result contract

Every released model must be accompanied by:

1. the matching JSON configuration;
2. the perception checkpoint;
3. the dynamics checkpoint;
4. SHA256 hashes in `checkpoints/MANIFEST.sha256`;
5. a `metrics.json` produced by the public evaluation command.

Until the weight download links and hashes are populated, full training
remains available and evaluation exits with an explicit missing-checkpoint
message.
